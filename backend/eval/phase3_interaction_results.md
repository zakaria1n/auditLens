# Phase 3 — interaction verification

On 2026-11-21 an isolated backend was started with commit `775b7c7d907f`
plus the in-progress Phase 3 changes and prompt version
`composition-v2-2026-11-21-3`. It used the previously persisted Phase 2
conversation generated by OpenCode CLI / `big-pickle`.

The first process-diagram step, `goal` / “Goal received”, was selected from
the stored composition. A structured conceptual context and the explicit
explanation-only flag were sent through the conversation stream. The model
returned an explanation of that step; the event stream contained no tool calls,
no mission was created, and the original assistant message remained available.
The provider does not stream tokens through this CLI adapter. The frontend's
separate jsdom integration test covers selecting a step and submitting the
corresponding context through `ChatCenter`; no browser was used.

The deterministic backend test additionally makes a simulated provider request
`create_audit` despite its absence from the permitted tools. The action is
refused and no mission is created. Conceptual visualizations do not expose
evidence access or investigation actions; verified evidence binding is outside
this phase. Malformed-JSON repair and persistence of repaired presentations
retain their Phase 2 limitations.
